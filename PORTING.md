### Detectors ported (5 of 49)

`StatsGapDetector` (client), `IceDisconnectedDetector`, `TransportDelayDetector` (peer connection),
`DryInboundTrackDetector`, `DryOutboundTrackDetector` (tracks). Between them they cover every
registration point and both detector shapes (stateful raise/resolve with a sliced window, and a
per-transport state map), so the rest follow the same pattern.

## Where the C++ differs on purpose

- **Events.** `on('x', fn)` becomes overriding `Listener::OnX()`. Several listeners can be added.
  Detector events pass the monitor they are about (the JS payload for `dry-inbound-track` carries
  only the client monitor).
- **Manual collection samples on every call.** With `collectingPeriodInMs = 0` and a
  `samplingPeriodInMs > 0`, each `Collect()` creates a sample. The JS library samples nothing
  without a collecting period.
- **`StatsGapDetectorConfig::expectedPeriodInMs`**, new, so the detector works when the
  application drives `Collect()` itself.
- **`dry` verdict.** The JS detectors set `dry = false` on every tick after raising, while the
  issue is still open. Here `dry` stays `true` until the issue resolves.
- **Ended outbound tracks** are dropped after their detectors' last look at the next collection,
  rather than waiting for their media source report to disappear.
- **Track context merge.** A field set in the new context overrides; there is no way to clear a
  single field by passing it as `undefined`.
- **Timestamps** are kept as `double` milliseconds and written as integers when whole.

## Untested

The libwebrtc and libmediasoupclient bindings are written against the API libmediasoupclient 3.5
uses (`webrtc::scoped_refptr`) but have not been compiled here, since that needs a libwebrtc
build. The core and everything under `test/` build and pass with ASan/UBSan and TSan.
