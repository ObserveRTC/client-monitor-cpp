### Breaking API changes: fix every use

- Stats adapters belong to the `ClientMonitor` now.
  - `PeerConnectionMonitor::AddStatsAdapter()` / `RemoveStatsAdapter()` are removed. Use
    `ClientMonitor::AddStatsAdapter()` / `RemoveStatsAdapter()` / `GetStatsAdapter(name)`.
  - `StatsAdapter::Adapt(nlohmann::json& stats)` is now
    `Adapt(const std::string& peerConnectionId, nlohmann::json& stats)`. Update every custom adapter.
  - The `ClientMonitor` starts with a `LibWebRtcStatsAdapter`. Do not add another one.
- `PeerConnectionMonitor::Collect()` is removed. Call `ClientMonitor::Collect()`, or rely on the
  monitor's collecting timer. `PeerConnectionMonitor::GetRawStats()` returns the collector's report
  if raw stats are needed. `PeerConnectionMonitor::Accept(report)` still exists and now goes through
  the client monitor's adapters.
- New and optional: `ClientMonitor::Listener::OnRawStats(clientMonitor, peerConnectionId, rawStats)`
  reports each raw report before adaptation.

Search for: `AddStatsAdapter`, `RemoveStatsAdapter`, `StatsAdapter`, `Adapt(`, `->Collect(`,
`.Collect(`.

### mediasoupclient binding: check that every hook is called

The binding has to know every producer's lifecycle, so that a closed producer's sender, which
libwebrtc keeps reporting, is not bound to a track. With
`observertc::clientmonitor::mediasoupclient::TransportMonitor`, check that the application calls:

- `Bind(transport)` once per transport, and `Close()` before the transport is closed;
- `OnProducerCreated(producer)` right after every `Produce()`;
- `OnProducerTrackReplaced(producer)` after every `ReplaceTrack()`, `ReplaceTrack(nullptr)` included;
- `OnProducerPaused()` / `OnProducerResumed()` when a producer is paused or resumed;
- `OnProducerClosed(producer)` whenever a producer is closed, also when it is closed and created
  again (a device change, a reconnect);
- the consumer, data producer and data consumer hooks, as before.

A missed `OnProducerCreated()` or `OnProducerClosed()` leaves the old sender bound to the track.
`examples/mediasoup_client.cpp` in the library shows the whole pattern. Nothing has to be
configured: the binding adds a `DetachedSenderStatsAdapter` to the client monitor for send
transports.

Without the mediasoupclient binding, if the application feeds its own `StatsCollector` and replaces
senders, add a `DetachedSenderStatsAdapter` to the `ClientMonitor` and call
`SetSenderTrack(peerConnectionId, mid, hasTrack)` whenever a track is attached to or removed from a
sender, and `RemovePeerConnection(peerConnectionId)` when the peer connection goes away.

### Behaviour changes (no code change expected)

- Stats timestamps in the samples are milliseconds; up to 0.2.0 they were libwebrtc's microseconds.
  Rates and detector timings computed by the library were 1000 times off before. If the project
  reads stats timestamps from the samples itself, it must read milliseconds now.
- `dry-outbound-track` no longer fires for a sending track after its producer is closed and created
  again.

### Verify, in addition to the general checks

- `outboundTracks[].attachments.producerId` matches the current producers.
- After closing and creating the producers again, no `dry-outbound-track` issue is raised for tracks
  that are sending, and each outbound track's RTP streams are the new producer's (the `outbound-rtp`
  `mid` equals the producer's `rtpParameters.mid`).
- Stats `timestamp` values inside `peerConnections[]` are milliseconds (13 digits before the decimal
  point, e.g. `1792044664814.755`), not microseconds (16 digits).
